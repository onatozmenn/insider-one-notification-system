# API

This document is the authoritative API contract until `api/openapi.yaml` lands in M1-7. After that, the OpenAPI file is the contract. This document explains the shape and the behaviour behind it.

## 1. Conventions

- Base path: `/api/v1`.
- JSON only, UTF-8.
- Timestamps are RFC3339 in UTC.
- IDs are UUIDv7, generated by the server.
- Every response includes `X-Request-ID`. If the client sends one, the server keeps it.
- `Idempotency-Key` is optional on create endpoints. When present, it must be 1 to 255 characters.
- Request body limit: 10 MB.
- Create endpoints return `202 Accepted` with a `Location` header.
- Read and cancel endpoints return `200 OK`.
- Errors use one shape:

```json
{
  "error": {
    "code": "validation_error",
    "message": "Request validation failed",
    "details": [
      {
        "field": "notifications[3].recipient",
        "reason": "must be a valid E.164 phone number"
      }
    ]
  }
}
```

## 3. Create one notification

```http
POST /api/v1/notifications
Content-Type: application/json
Idempotency-Key: 7c1f5b0e-2a4d-4c8e-9f11-3b6a8d2e4f90

{
  "recipient": "+15555550100",
  "channel": "sms",
  "content": "Your order has shipped.",
  "priority": "high"
}
```

| Field | Type | Required | Notes |
| --- | --- | --- | --- |
| `recipient` | string | yes | Channel-specific format. |
| `channel` | string | yes | `sms`, `email`, or `push`. |
| `content` | string | yes | Body. Limits depend on the channel. |
| `subject` | string | email only | Email subject. Also used as the push title. |
| `priority` | string | no | `high`, `normal`, `low`. Default `normal`. |
| `scheduled_at` | string | no | RFC3339. Bonus feature. Future, at most 30 days ahead. |
| `template` | string | no | Template name. Bonus feature. |
| `variables` | object | no | Template values. Bonus feature. |

Response:

```http
HTTP/1.1 202 Accepted
Location: /api/v1/notifications/0193b2f4-7c1a-7d3e-9a10-5f8c2d6e4b71
X-Request-ID: req_01J...
Content-Type: application/json
```

If Redis is unavailable, the notification is persisted as `pending` and the response is still `202`. The reconciler enqueues it when Redis returns. Use an `Idempotency-Key` if the client may retry.

```json
{
  "id": "0193b2f4-7c1a-7d3e-9a10-5f8c2d6e4b71",
  "batch_id": null,
  "recipient": "+15555550100",
  "channel": "sms",
  "subject": null,
  "content": "Your order has shipped.",
  "priority": "high",
  "status": "queued",
  "attempt_count": 0,
  "max_attempts": 5,
  "scheduled_at": null,
  "next_attempt_at": null,
  "provider_message_id": null,
  "last_error": null,
  "created_at": "2026-11-17T17:00:00Z",
  "updated_at": "2026-11-17T17:00:00Z",
  "accepted_at": null,
  "cancelled_at": null
}
```

## 4. Create a batch

```http
POST /api/v1/notifications/batch
Content-Type: application/json
Idempotency-Key: batch-2026-11-17-001

{
  "notifications": [
    {
      "recipient": "+15555550100",
      "channel": "sms",
      "content": "Flash sale starts now.",
      "priority": "high"
    },
    {
      "recipient": "onat@example.com",
      "channel": "email",
      "subject": "Your weekly summary",
      "content": "Here is what happened this week.",
      "priority": "normal"
    }
  ]
}
```

Rules:

- `notifications` contains 1 to 1000 items.
- Validation is all-or-nothing. If one item is invalid, nothing is inserted.
- Item errors use the array index in the `field` value.

Response:

```json
{
  "batch_id": "0193b2f4-8d2b-7a4f-bc21-6a9d3e5f7c82",
  "total": 2,
  "status": "processing",
  "status_url": "/api/v1/batches/0193b2f4-8d2b-7a4f-bc21-6a9d3e5f7c82",
  "created_at": "2026-11-17T17:00:00Z"
}
```

## 5. Get one notification

```http
GET /api/v1/notifications/0193b2f4-7c1a-7d3e-9a10-5f8c2d6e4b71
```

Returns the same object as the create response. `404` if the ID does not exist.

## 6. List notifications

```http
GET /api/v1/notifications?status=accepted&channel=sms&from=2026-11-01T00:00:00Z&to=2026-12-01T00:00:00Z&page=1&page_size=50
```

| Query | Type | Default | Notes |
| --- | --- | --- | --- |
| `status` | string | none | One status. |
| `channel` | string | none | `sms`, `email`, `push`. |
| `batch_id` | string | none | UUID. |
| `from` | string | none | RFC3339, inclusive. Filters `created_at`. |
| `to` | string | none | RFC3339, exclusive. Filters `created_at`. |
| `page` | int | 1 | Minimum 1. |
| `page_size` | int | 20 | Minimum 1, maximum 100. |

Ordering is `created_at DESC, id DESC`.

## 7. Cancel a notification

```http
POST /api/v1/notifications/0193b2f4-7c1a-7d3e-9a10-5f8c2d6e4b71/cancel
```

Allowed only when the status is `pending` or `scheduled`. Returns `200` with the updated notification.

`409 Conflict` when the status is `queued`, `processing`, `accepted`, `failed`, `cancelled`, `dead_letter`, or `delivered`.

```json
{
  "error": {
    "code": "not_cancellable",
    "message": "Only pending or scheduled notifications can be cancelled",
    "details": []
  }
}
```

## 8. Batch summary

```http
GET /api/v1/batches/0193b2f4-8d2b-7a4f-bc21-6a9d3e5f7c82
```

Batch status is derived from the children: `pending`, `processing`, `completed`, `partial_failure`, `failed`, `cancelled`, or `mixed`. If Redis was unavailable at creation time, the batch is accepted as `pending` and the reconciler enqueues it later.

```json
{
  "batch_id": "0193b2f4-8d2b-7a4f-bc21-6a9d3e5f7c82",
  "total": 1000,
  "status": "processing",
  "counts": {
    "pending": 0,
    "scheduled": 0,
    "queued": 100,
    "processing": 20,
    "accepted": 870,
    "failed": 2,
    "cancelled": 8,
    "dead_letter": 0,
    "delivered": 0
  },
  "created_at": "2026-11-17T17:00:00Z",
  "updated_at": "2026-11-17T17:00:02Z",
  "status_url": "/api/v1/batches/0193b2f4-8d2b-7a4f-bc21-6a9d3e5f7c82",
  "notifications_url": "/api/v1/notifications?batch_id=0193b2f4-8d2b-7a4f-bc21-6a9d3e5f7c82"
}
```

## 10. Error codes

| Code | HTTP | When |
| --- | --- | --- |
| `validation_error` | 422 | Invalid field, unknown channel, content too long. |
| `not_found` | 404 | Notification or batch does not exist. |
| `not_cancellable` | 409 | Cancellation is not allowed in the current status. |
| `idempotency_conflict` | 422 | Same key, different request body. |
| `idempotency_in_progress` | 409 | The original request with this key is still running. |
| `payload_too_large` | 413 | Body exceeds 10 MB. |
| `unsupported_media_type` | 415 | `Content-Type` is not JSON. |
| `service_unavailable` | 503 | PostgreSQL is not ready. A Redis outage accepts creates as `pending`; the reconciler enqueues them later. |
| `internal_error` | 500 | Unexpected failure. The request ID is in the response. |

## 11. Idempotency

- The key is scoped by endpoint. The same key on a different endpoint is a different request.
- The server stores a SHA-256 hash of the canonical JSON body.
- Same key and same hash:
  - If the original request completed, the stored response is returned with `Idempotent-Replayed: true`.
  - If it is still running, the server returns `409 idempotency_in_progress`.
- Same key and a different hash: `422 idempotency_conflict`.
- Keys expire after 24 hours.
- Without a key, the server does not deduplicate API calls. The worker still guards against duplicate sends.
